CORE FEATURES:
─────────────────────────────────────────────

1. WEEKLY MEAL PLAN VIEW
- Show all 7 days in a weekly calendar layout
- Each day shows the activity (Badminton / Football / Rest)
- Each day has 4–5 planned meals with time, meal name, food description, and macros (calories, protein, carbs, fat)
- Use the following weekly plan data as default content:
    Mon–Thu: Badminton 8–9am
    Fri: Football 9–10:30pm
    Sat: Light activity
    Sun: Full rest day

2. DAILY VIEW (tap any day to open)
- Show planned meals in a timeline layout by time of day
- Each meal card shows: time, meal type, food name, cal/protein/carb/fat
- Show a daily macro progress bar (planned vs target)
- A floating "+" button to log actual food eaten

3. FOOD LOGGER (the key feature)
- User can tap any planned meal and mark it as "Eaten as planned" OR "Log what I actually had"
- If logging actual: show a form with fields:
    * Food name (text input)
    * Calories (number)
    * Protein (number)
    * Carbs (number)
    * Fat (number)
    * Optional note
- After logging, the meal card updates to show actual vs planned side by side
- Color code the difference:
    * Green if within 10% of target
    * Orange if over/under by 10–20%
    * Red if over/under by 20%+

4. DAILY MACRO DASHBOARD
- At top of each day view show 4 macro rings/progress bars:
    * Calories (target: 2,200–2,400)
    * Protein (target: 160–170g)
    * Carbs (target: 220–250g)
    * Fat (target: 60–70g)
- Show: Planned | Logged | Remaining
- Remaining turns red if over target

5. WEEKLY PROGRESS SUMMARY
- A summary screen showing all 7 days
- Bar chart or visual showing daily calories: planned vs actually logged
- Weekly averages for all 4 macros
- A streak counter: "X days this week you hit your protein target"
- Days where no logging was done shown as "Not logged yet"

6. SNACK SUGGESTIONS PANEL
- A tab or bottom sheet showing snack options categorised as:
    * High Protein
    * Pre-Workout
    * Evening / Pre-Bed
    * Calorie Boost
- Each snack shows cal/protein/carbs/fat and best timing
- User can tap "Add to today" to log a snack directly

─────────────────────────────────────────────
UI / UX REQUIREMENTS:
─────────────────────────────────────────────
- Mobile-first design optimised for phone screen
- Primary colors: Dark green (#1A5276) and white, accent: (#1E8449)
- Clean card-based layout with subtle shadows
- Bottom navigation bar with 4 tabs: Today | Week | Log | Snacks
- Smooth transitions between views
- Use Recharts for all charts and graphs
- Use emoji icons for meals and activity types
- All data persisted using window.storage API so logs survive between sessions

─────────────────────────────────────────────
DATA STRUCTURE (window.storage):
─────────────────────────────────────────────
Store the following structure:

{
  "weekPlan": { ...7 days of planned meals... },
  "logs": {
    "YYYY-MM-DD": {
      "meals": [
        {
          "mealId": "mon-breakfast",
          "loggedFood": "Egg bhurji + toast",
          "calories": 420,
          "protein": 28,
          "carbs": 35,
          "fat": 16,
          "note": "Added extra egg",
          "status": "logged_actual"
        }
      ],
      "water": 2500
    }
  }
}

status can be: "planned" | "eaten_as_planned" | "logged_actual" | "skipped"

- Streak counter on weekly summary: "X days this week you hit your protein target"

─────────────────────────────────────────────
TECH STACK:
─────────────────────────────────────────────
- React with hooks (useState, useEffect, useCallback)
- Tailwind CSS for styling (core utility classes only)
- Recharts for charts (import from "recharts")
- window.storage API for persistence
- Single file React component with default export
- No required props
- Do NOT use localStorage or sessionStorage
